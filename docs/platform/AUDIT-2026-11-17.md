# Pleadli audit and staged plan, 2026-11-17

Read-only review. Numbers below were measured in the repo today; anything marked **unverified** was not checked.

## 2. Critique, no padding

1. **Breadth outran verification.** Five apps of 15k to 55k lines each, 4 TypeScript tests and no PR gate. The risk is not missing features, it is untested ones. Your own notes say Courts and Lawyers were written unrun, LAN exchange was never run on two machines, and several apps were never seen in a real Tauri window. Justice software is trusted only after it has survived real use.
2. **Five apps, five copies of the same skeleton.** Each has its own `api/mod.rs` (1.4k to 1.9k lines), shell, settings, backup glue and i18n wiring. `node-core` and `setup` share some of it, but the duplication is the main cost driver for every future change (a security fix is applied five times).
3. **Rust robustness.** Up to 1,015 `.unwrap()` calls outside test files. That figure includes inline test modules, so it needs triage, but production panics on a custody record are not acceptable. 170 `any` in TypeScript.
4. **Giant files.** `police/api/mod.rs` 1,885 lines, `dpp/api/mod.rs` 1,463, `lawyers/api/mod.rs` 1,402, `lawyers/settings/panes.tsx` 1,081. These should be split by domain.
5. **Performance habits that fight "Apple smooth".** `@pleadli/ui/globals.css` applies a colour transition to `*` (every element, on every theme or state change), hides all scrollbars globally, applies a dual-tone icon animation to every `svg`, and ships a legacy cream palette that `workspace.css` overrides. The `@source` globs make the UI package scan every app. Client JavaScript is large for an offline desktop app.
6. **"Apple-grade" needs budgets, not adjectives.** These are WebView apps (WebView2 on Windows). They can feel excellent, but only if cold start, route change, scroll and input latency are measured against targets. None are measured today.
7. **Windows publisher verification is "separate"** (release notes say so). Unsigned or unverified installers trigger SmartScreen warnings. That alone can kill a government or firm demo.
8. **No revenue path in code.** Orchestra issues licences and keys, but there is no payment flow (mobile money, card, invoice). Purchases are listed as a requirement and are absent.
9. **No pilot, no references, no figures.** Nothing on the website can honestly claim adoption yet.
10. **Docs sprawl.** Dated snapshots (`...-2026-10-12.md`) beside living plans make it hard to know what is current.

## 3. What is missing, by area

**Interoperability (files first)**
- Present: DOCX and XLSX export, print, PDF, verify link.
- Missing: Google Drive, Docs, OneDrive, Dropbox (no connector code found; Google appears in 4 files only). No DOCX round-trip (edit in Word, return to the file). No watched-folder sync.

**Communication between institutions and civilians**
- Present: LAN exchange (unrun on two machines), Orchestra relay endpoints.
- Missing: any inter-institution protocol across the internet, any civilian surface, consent and sharing grants, delivery receipts.

**Identity**
- Missing: National ID (NIN) verification. Nothing in code. Access to NIRA verification requires an agreement with the government; do not assume it.

**Roles, purchases, keys**
- Missing or partial: role-based access inside an office (Police roles and vault sealing flagged as unfinished), seat management in Cloud, payment and invoicing, key rotation and recovery policy.

**Security**
- Present: SQLCipher, sealed vault, keystore, pinned-TLS LAN.
- Missing: written threat model, independent security review, SBOM and dependency audit in CI, signed Windows publisher, hardware-backed key use where available, per-record audit export.

**AI**
- Missing: no model-provider layer found in code (no key handling, no provider choice, no redaction). The `/docs/ai` page describes a position, not a feature.

**Extensions**
- Missing: all "plugin" hits are Tauri plugins. There is no extension API, manifest or permission model.

**Mobile**
- Missing: Android and iOS for Police, any civilian app, maps and routing, plate scanning.

**Website and marketing**
- Present: home, products, roadmap, downloads (reads releases from `getReleases`), docs, about, contact, licensing, verify, track, i18n en/sw/fr.
- Missing: pricing, trust and security page, changelog and release notes per version, docs search, country pages, status page, proof (pilots, quotes), per-OS download detection, release channels, the showcase film.

**Platform reach**
- Missing: macOS and Linux builds, ARM Windows, auto-update parity on those.

## 4. Decisions to settle before building

1. **Civilian contact is opt-in per institution and per case.** A station turns the civilian portal on; a civilian creates a request that gets a reference number and QR, with no account needed for the first contact. Nothing is pushed to anyone who has not switched it on.
2. **Emergency is not Pleadli's job.** Civilian "get help" must hand off to 999 or 112 and never replace them. A false sense of coverage is the largest safety risk of the mobile idea.
3. **Plate scanning is a police-only, policy-gated, audited feature.** For civilians it is a surveillance and abuse risk.
4. **Cloud documents are connectors, off by default** for Police and Prisons. Evidence leaving the device is a policy decision for the institution.
5. **Inter-institution link is store-and-forward and end-to-end encrypted**, relayed through Orchestra. Recipients pull; senders get receipts. Cloudflare sees ciphertext only.
6. **AI is bring-your-own and off by default.** Keys live in the OS keystore, an institution admin chooses allowed providers, every prompt is logged locally, and a local-model option (for example Ollama) works offline.
7. **Plugins come after the seams.** Design the extension boundary now (manifest, declared permissions, sandboxed runtime) but ship the first plugin only after the core is stable.

## 5. What Apple would do in 2026

- One product feeling, many apps: the same command palette, keyboard map, settings, search and undo everywhere.
- Instant: cold start, tab switch and scroll are budgeted and measured on the lowest-spec machine you support.
- Privacy as the headline: work happens on the device, the cloud carries ciphertext.
- Continuity: start a record on mobile, finish on desktop, because Orchestra is the sync fabric.
- Fewer options, strong defaults, one primary action per view.
- Updates are invisible and safe: staged rollout, rollback, release channels.
- Be honest about hardware: GPU is used by the compositor; NPU only matters for on-device models (OCR, speech), reached through platform APIs (Windows ML, Android ML Kit, Apple Vision), not from the WebView.

## 6. VS Code ideas worth borrowing

Single downloads page that detects the OS and offers stable and early-access channels; a release-notes page per version; docs with search and a "what's new" link inside the app; a command palette; workspace trust; settings and profiles; an extension manifest with declared permissions; telemetry that is opt-in and documented. Not worth borrowing yet: a public marketplace.

## 7. Cost on Cloudflare

Keep the Cloud thin: local-first apps cost nothing per user; spend happens only on the relay, backups (R2) and licence checks (D1). Make the relay stateless and pull-based, cap sizes, rate-limit per licence, and put backups on R2. Check current Cloudflare pricing before committing to numbers (unverified here).

## 8. Staged plan (one stage at a time, test before the next)

**Stage 0. Hygiene and gates (about one week)**
- PR CI: typecheck, `cargo test`, `cargo clippy`, bundle-size and unwrap budgets.
- Triage `unwrap`, `any`; split the four giant files; delete or archive dated docs; remove the legacy cream palette; drop `*` transitions and global scrollbar hiding; narrow the UI `@source` globs.
- Add the performance budget doc (cold start, route change, idle memory, installer size) and measure the current numbers.

**Stage 1. One app made trustworthy: Lawyers**
- Fastest paying customer. Run it in the real window, fix what breaks, add integration tests, and write the pilot checklist.
- Add the revenue path in Orchestra: mobile money and card or invoice, seats, key issue and revoke.

**Stage 2. Shared platform core**
- Move the duplicated shell, API skeleton, backup, settings and roles into shared crates and packages so a fix lands once.
- Roles and permissions model; command palette; key recovery policy.

**Stage 3. Files that travel**
- DOCX round-trip and watched folder; Drive and OneDrive as opt-in connectors with narrow scopes.

**Stage 4. Pleadli Link and the civilian portal**
- Signed, end-to-end encrypted envelopes with receipts, opt-in per institution.
- Civilian portal as a responsive web or installable web app first. Native mobile only after.

**Stage 5. Mobile for Police**
- Android first, iOS after. Traffic and on-duty flows, maps, nearest unit. Plate scanning behind policy.

**Stage 6. Identity, BYO AI, extensions**
- NIN verification through a provider adapter (needs a government agreement).
- Provider-agnostic AI gateway with admin policy and audit.
- Extension manifest and first sandboxed plugin.

**Stage 7. Website for the world, then the film**
- Pricing, trust centre, changelog, country pages, status, docs search, release channels, proof from pilots.
- A 45 to 60 second film made from real screen recordings, after the product is stable.

**Stage 8. Security and reach**
- Independent review, signed Windows publisher, SBOM, macOS and Linux builds.

## 9. Recommendation

Do Stage 0 immediately, then Stage 1. Do not start mobile, plugins or AI before the gates and one trusted app exist. The ideas are good; the order matters more than the list.

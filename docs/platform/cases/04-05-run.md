| Step | Result |

| Judge refuses bail: sitting held with the outcome, order issued, both sent | Firm matter holds two notes: the order's full wording, and "Court record of the bail application on 3 December 2026 ... Held. Application heard. State opposed. Bail refused." |

Findings:
1. The firm's diary still lists the bail hearing as "scheduled" with Attended/Adjourned buttons (by design: attendance is the advocate's record). Nothing on the hearing row says the court has recorded an outcome. The advocate must find the note.
2. Nothing tells the firm what to do next. The order says "he may apply again if circumstances change", but no deadline or follow-up task appears (an appeal or fresh application is the advocate's move; the app only counts days once an event is recorded).
3. The matter's **Papers** tab shows "Filings: Nothing has been filed. Draft a document first." directly above a list of two filings made to the court. Two different notions of "filing" on one screen contradict each other.
4. The accused is recorded "remanded" at the firm, but Prisons is not in this case, so no production or remand order was tested.

Police now quotes the DPP's file key from its latest decision notice on that case when the notice was a return (`apps/police/.../exchange.rs`). Proven live. Not unit tested.
2. **Fixed (later 2026-11-24): the silent refusal.** Police let an officer take a statement from a person not on the case and sent it; DPP refused the whole referral with a message naming nothing, and the station never heard. Now (a) Police refuses to build the referral and says who: "Agnes Lamunu gave a statement on this case but is not listed on it. Add them to the case, for example as a witness, and refer again." (same for a charge naming someone not on the case), proven live; (b) if a referral still arrives that DPP cannot take in (authentic sender, bad content), DPP now quotes the statement in its message, sends the station a signed "rejected" receipt with the reason (once, even if the package arrives twice), and keeps nothing; regression test in DPP `api/tests.rs`. Not seen in a window: Police showing that rejected receipt on the referral. A referral record is still created in Police before the export fails, leaving a "pending" one behind.
3. **Not fixed: the Police referral list still says "accepted" for CRB 452/2026 after DPP returned the file.** The returned state is only in the decision notice, not on the referral.
4. The directions sent as plain words are good. Whether Police shows them on the case and as tasks was not looked at (Police window not signed in, PIN unknown).
5. My own script accepted an old stale referral into the test copy of DPP data and created one duplicate file (fb354d4d) for CRB 452. Test data only, not fixed.

## Update: DPP file stage follows a sanction (2026-11-24, last)

A decision to charge (sanction or threshold charge) recorded by hand now moves a file still at receive, review or decide on to "prepare" (`apps/dpp/src-tauri/src/domain/decisions.rs`). Decline, discontinue, return and the other decisions leave the stage alone, because moving to "concluded" needs an outcome and "return" is not an end.
